# vault

A personal Obsidian-based organisation and agent orchestration system.

Every work item is one Markdown file. A board is a rendered view of one item's children grouped by
status. Any card can be promoted into a board, so the hierarchy is unlimited without a deep folder
tree or multiple task abstractions.

Markdown is canonical. The plugin is a view, never the database.

## Layout

```text
CLAUDE.md     how to work in this repo, and the traps
docs/STATUS.md  where the work stands
src/shared/   schema, frontmatter and transition rules, used by both writers
src/cli/      the wi CLI, plain Node
src/plugin/   the Obsidian plugin, which must also load on iOS
build/        esbuild, the iOS import guard, the plugin installer
scripts/      the vault's hook and committer, and the dev fixture generator
docs/         design decisions, produced by grilling the spec
test/         disposable dev vault; its Boards/ is generated by npm run fixture
.lavish/      design review artifacts
obsidian_recursive_board_spec.md   the original architecture spec
```

Nothing in `src/shared/` imports from Node, so the plugin can carry it to iOS. That is what keeps
the CLI and the plugin applying the same rules rather than two drifting copies of them.

## The wi CLI

`wi` owns every write an agent or a script makes, so the integrity rules live in tested code
rather than in prose. It is plain Node with no dependencies and no Obsidian import. Node 23.6 or
later runs the TypeScript directly, so there is no build step.

```bash
wi new "Build server" --parent Main     # create a child work item
wi status wi-a7f3 doing                 # move a card between columns
wi move wi-a7f3 --to "Build server"     # move a card to another board; its status stays
wi children Main --tree                 # read a board, or a whole subtree
wi rm wi-a7f3 --recursive --dry-run     # what a removal would take, touching nothing
wi validate                             # exits 1 when the vault has errors
wi template write                       # regenerate Templates/ from the code
```

Every command takes an id, a filename or a title. Add `--json` for machine-readable output.
Point it at a vault with `--vault <path>` or `$WI_VAULT`; otherwise it walks up to the nearest
folder holding `Boards/`.

Unticking a done item is `wi status <ref> <its prev_status>`, which also clears the record.
`wi validate` exits 1 on an error, so it works as a pre-commit hook on the vault repo.

## Keeping the vault's history

Agents may delete work items (`wi rm`), and much of what they do goes unreviewed. The safety net
is therefore structural rather than supervisory, and it has two halves:

```bash
node scripts/vault-git.mjs install-hook  --vault <path>   # refuse a commit that records damage
node scripts/vault-git.mjs install-timer --vault <path>   # commit the vault on an interval
node scripts/vault-git.mjs status        --vault <path>
node scripts/vault-git.mjs uninstall     --vault <path>
```

They fail differently on purpose. The hook **blocks** a commit that would record an invalid vault,
because a person is there to read why. The timer **commits anyway** and records the validation
result in the message, because a broken vault is the state most worth having history for.

Both are installed on the production vault. The dev fixture gets neither, because it is
deliberately invalid so the plugin can be built against the awkward cases.

```bash
npm test          # typecheck, then 282 tests
npm run fixture   # regenerate test/Boards/, with dates relative to today
```

## The Obsidian plugin

Renders a work item's children below the note as a checklist, which Obsidian itself renders from
generated Markdown (decision R1). Promote an item and it becomes a board that fills the pane:
four columns on the Mac, four status tabs on the phone. A right click on a card (the ⋯ button on
the phone) opens every verb: status, Move to…, promote, copy id, remove. "Undo last board action"
reverses the plugin's own writes. It reads frontmatter through Obsidian's own metadata cache, so
no note body carries query text (decision D4).

```bash
npm run build          # dist/obsidian-recursive-board/{main.js,manifest.json,styles.css}
npm run dev            # the same, rebuilt on every save
npm run link:dev       # symlink the build into the test/ dev vault
npm run install:vault -- --vault <path>   # copy into a real vault, including the iCloud one
```

`--link` is refused for a vault inside iCloud Drive, because iCloud does not sync a symlink and
the phone would silently get nothing (decision D6). Obsidian loads a new build only on reload;
on the phone, force-quit it. The phone has no console, so the plugin has a "Write a layout report
for debugging" command whose output iCloud brings back to the Mac.

### The iOS constraint

One `node`, `fs`, `path`, `child_process` or `electron` import makes the plugin fail to load on
iOS, silently. Three things stop that, none of them discipline:

1. `tsconfig.plugin.json` has no `@types/node`, so such an import cannot typecheck.
2. `build/forbidden-imports.mjs` fails the esbuild run.
3. `src/plugin/ios-safety.test.ts` scans the source tree and the built bundle.
