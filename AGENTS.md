# Recursive Board

An Obsidian plugin that renders work items as boards and checklists, and `wi`, the CLI that
writes them. Every work item is one Markdown file.

**Markdown is canonical. The plugin is a view, never the database.**

## Read first

[`README.md`](README.md) says what the product does and how a user installs it.

[`docs/adr/`](docs/adr/) records every decision the shipped product rests on, one per file. Read
the ADRs that cover what you are about to change. When your change contradicts one, amend it in
the same commit, or add a new ADR that supersedes it.

`test/AGENTS.md` is a different kind of document: the rulebook for an agent working **inside a
vault**, not on this code. Edit it when agent authority over vault contents changes.

## Traps

**`test/` is a deliberately invalid vault.** It is the dev fixture, and it must carry
the awkward cases: an item whose parent does not resolve, a duplicate title, an unknown
frontmatter key. `wi validate --vault test` reports one error and one warning, and that is the
fixture working. `test/Boards/` is generated by `npm run fixture` from `scripts/fixture.ts`, with
dates relative to today, and is not committed. Change the fixture there, never by hand.

**`src/shared/` and `src/plugin/` import nothing from Node.** One `node:` import makes the plugin
fail to load on iOS, silently. Guaranteed three ways: `tsconfig.plugin.json` carries no Node
types, `build/forbidden-imports.mjs` fails the build, and `src/plugin/ios-safety.test.ts` scans
the source tree and the built bundle. Put filesystem work in `src/cli/`.

**`src/shared/` is the single source of truth for every rule both writers apply.** A card ticked
in Obsidian and `wi status <id> done` must do the same thing. Schema, frontmatter editing, status
transitions, templates and labels live there; adding a rule to one side alone is how they drift.

**Frontmatter is edited line-wise and never reserialised.** `src/shared/frontmatter.ts` rewrites
the one line it was asked to change and copies every other byte. That is what preserves unknown
keys and keeps a card move to a one-line diff. A YAML library would look like an improvement and
would break both. This one is held by tests alone.

**One file per operation.** A card's status and its parent live in the child. Never write to a
parent to record something about a child: that property is what makes a move safe on a synced
vault, and losing it is not visible until two devices conflict.

## Working here

Node 26 runs the TypeScript directly, so there is no build step for the CLI. `npm test`
typechecks both projects and runs every test; `npm run build` produces the plugin.

Write tests first for anything in `src/cli/` or `src/shared/`. A bug there corrupts canonical data
silently, which is the reason the CLI exists at all.

The plugin is not covered by tests beyond its pure logic and a bundle-loads check. Verify a change
to it by reloading Obsidian on a test vault and looking.
